# 2026-04-14 — Fixed Orientations Bug Fix + Roll Unwrap + Instagram Video

## fix-orientations.ts: Double R2D Bug (FIXED)
- **Root cause**: `applyInverseDKE()` already returns deg/s internally (multiplies by R2D). Our fixed pass multiplied by R2D again → 57.3x inflation of all rates and accelerations.
- **Fix**: Removed the extra `* R2D` on the fixed rate/acceleration assignments.
- After fix, re-derived rates match original pipeline rates during freefall, and patched sections (ground, exit, deployment) have smooth continuous rates with no visible boundary artifacts.
- Removed the workaround that copied `bodyRates` during unpatched phases — re-derived rates now used everywhere.
- Removed `[ArcDebug]` console log from `gps-aero-overlay.ts`.

## Pipeline: Unwrapped Angles Written Back to pt.aero (NEW)
- **Problem**: `pt.aero.roll` stored raw wrapped values from `Math.acos` ([-π, π]). During 540° corkscrew (05-04-25 flight), roll wraps from -178° to +178° at t≈56.25s. This caused:
  - GLB model orientation snap (quaternion sign flip from `sin(-178°) ≠ sin(+178°)`)
  - Force arrow discontinuities
  - Rate spikes in any code reading `pt.aero.roll` directly
- **Fix**: In `gps-pipeline.ts` Step 6, after SG smoothing + unwrap, write `smoothPhi`, `smoothTheta`, `smoothPsi` back to `results[i].aero.roll/theta/psi`. All downstream consumers now see continuous unwrapped angles.
- Same issue existed for heading (`psi`) via `Math.atan2` wrapping at ±π.

## Key Lesson
- `applyInverseDKE()` in `wse.ts` returns **deg/s** not rad/s — it has `R2D` conversion built in (line: `rates.push({ p: p * R2D, q: q * R2D, r: r * R2D })`)
- Original pipeline spreads these values directly into `bodyRates`; any code re-using `applyInverseDKE` output must NOT multiply by R2D again

## 3DATAERO Project Proposal

Hartman proposed a new project: **3DATAERO (3D Athlete Tracking + Aerodynamic Reconstruction)** — AI-powered platform that reconstructs aerodynamics of human flight from body-mounted 360° video + GPS/IMU data.

**Core idea**: Pair 360° camera frames (pose estimation → skeleton) with FlySight GPS aero pipeline (ground-truth forces, coefficients, control inputs). Learn the mapping from body pose → aerodynamic state. Nobody else has both sides of this equation.

**Key differentiator from Intel 3DAT**: 3DAT measures what the body *did*; 3DATAERO measures what the body did *and what it caused aerodynamically*.

**Hardware**: Insta360 X4 (8K @ 30fps) + FlySight 2 — ~$1K consumer gear vs millions for venue installations.

**Advantages of body-mounted 360°**: No occlusion, full surround view, consistent viewpoint, goes anywhere (cliffs, open sky).

**Challenges**: Pose estimation on wingsuit silhouettes (unusual body shape), equirectangular distortion, time sync between camera and GPS clocks, proprietary camera file format (sensor data extractable via existing tools), 8K data rate (~200 MB/s raw, 5-15 GB compressed per jump).

**Phases**: (0) Foundation — already built. (1) Paired dataset construction — tooling + time sync. (2) Pose estimation for flight — fine-tune existing models. (3) Learned aero mapping — pose → coefficients. (4) Applications — video-only reconstruction, real-time HUD, training tool, community platform.

**People**: Kenny Daniels has ML experience and BASEline video/sensor processing background — relevant collaborator.

**Document**: `docs/3DATAERO.md` — full project proposal with scope, risks, architecture, phasing, data rates, name discussion.

### angleLerp Fix
- **Root cause**: deployment transition interpolated `frozenRoll ≈ 2π` → canopy target `≈ 0` as a 360° rotation instead of recognizing same angle
- **Fix**: `angleLerp()` normalizes diff to [-π, π] before interpolating (shortest angular path)
- Applied to both deployment AND exit transitions in `fix-orientations.ts`
- **Result**: Hartman confirmed — "all of those bad artifacts are gone", vectors match GLB model through exit → deployment → canopy, realistic dynamics, no phantom roll moments

### Key Decisions
- **Fixed writeback includes angles**: Hartman explicitly requested writing `pt.fixed.roll/theta/psi` back to `pt.aero` despite risk of affecting CL/CD calculations — the phase corrections are the whole point
- **Trail instead of full scatter**: 8-second trailing window keeps charts clean while showing recent flight path context
- **Chart rebuild per frame**: For polar/speed views, `rebuildChart1()` called each frame (trail changes every frame). L/D view does lightweight cursor-only update. Acceptable perf for playback + Playwright capture.
- **Canopy polar same sweep infrastructure**: No special canopy sweep logic — just swap segments/polar/massRef based on flight mode. Canopy solver inputs may need work later but the chart visualization is ready now.
