# 2026-03-09 — Bridle Architecture Clarification

## Bridle Refactor Session

### Key Architectural Decision: Bridle Module Boundary
- **`bridle-sim.ts` should ONLY be PC + 10 segments** — no canopy bag, no suspension lines, no line stretch detection
- API: `step(anchorPos, anchorVel, rho, dt)` — anchor-agnostic chain that trails from whatever point it's given
- Runs identically during wingsuit deploy AND canopy flight
- **Current implementation is WRONG** — BridleChainSim absorbed canopy bag + suspension lines, which are deployment-only concerns

### Correct Module Responsibilities
- **`deploy-wingsuit.ts`**: Owns BridleChainSim + ALSO simulates canopy bag + suspension lines (deployment abstractions). Handles pin release, bag spawn, bag tumble, line stretch detection. At line stretch: freezes snapshot, hands bare bridle to sim-runner, bag+lines disposed.
- **`sim-runner.ts`**: Takes bare bridle ownership at line stretch. Steps with canopy bridleTop as anchor. No bag, no lines, no deployment logic.
- Bag + suspension lines are scaffolding — exist to get geometry right during deployment, then go away.

### Anchor Position State Machine
1. Wingsuit freefall: `bodyToInertial(container_back, ws attitude)`
2. Pin release: `canopyBag.position` (inertial)
3. Line stretch: transitions to `bodyToInertial(bridleTop, canopy attitude)`
4. Canopy flight: same as 3, continuously updated

### Tension Model Discussion
- Current implementation uses position-clamp (inelastic distance constraint), NOT springs
- One-directional propagation — body never feels tension from PC drag
- Real bridle stretch: ~5cm total over full length at extreme load (~250N)
- Recommended: stiff spring model with sub-stepping at 1000Hz (5 inner iterations per 200Hz outer tick)
- `k_total = 5000 N/m`, `k_seg = 50,000 N/m` (10 springs in series)
- Added §8 to BRIDLE-REFACTOR.md documenting current vs correct approach
