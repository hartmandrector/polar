## Today's New Work — Lift-Balance Retune

### Problem

Pre-retune leg/torso lift ratio at trim band was **2.85×** (leg=539 N,
torso=189 N at α=12°, V=45). Physically the leg wing has 2.3× the area
but is body-shadowed, lower-AR, and triangular-tapered, so it should not
generate that much more lift than the torso. The legacy `cm_alpha=0.60`
on the leg polar was acting as a "crutch" — adding a fake nose-up moment
that masked the lift-arm imbalance.

### Method (single-knob iteration with sweep + diff)

Added a dev hook in `main.ts`:

```js
window.__polar.lastSystemView   // { cl, cd, cm, ld, segmentForces[], ... }
window.__polar.lastFlightState
window.__polar.lastReadout
```

Drove sliders by HTML id (`alpha-slider`, `airspeed-slider`) via Playwright,
swept V × α, dumped JSON to `state/trim-baselines/`, diffed in PowerShell.

### Step 1 — leg cm_alpha 0.60 → 0

Removed the cm_alpha crutch. System pitch stability now purely lift × lever
arm (torso AC at +0.22 m, leg AC at −0.32 m). Trim α dropped from ~5.8° to
~3.5° — the imbalance was now fully visible.

### Step 2 — three-knob lift redistribution (user OK'd bundling)

- `A5_TORSO_POLAR.cl_alpha`        2.2 → **2.8** (head-deflected flow + arm roots)
- `A5_TORSO_POLAR.alpha_stall_fwd`  28 → **38** (flare margin, match leg)
- `A5_LEG_POLAR.cl_alpha`          3.2 → **2.4** (low-AR hindwing in body wake)

### Result

| Metric | Pre-retune | Step 2 |
|---|---:|---:|
| Trim α (CM=0) | ~5.8° | **5.25°** |
| CL at trim | ~0.30 | 0.272 |
| L/D at trim | ~2.4 | 2.35 |
| L/D max (~α=10°) | ~2.99 | 2.90 |
| Leg/torso ratio @α=8° | 2.58× | **1.51×** |
| Leg/torso ratio @α=12° | 2.85× | 1.64× |

User flew it in the GPS viewer in parallel — confirmed visually better,
good range, accessible stall point, plenty of steep range. Solver
re-validation confirmed convergence still holds.

## Deferred (with note in code)

**Step 2b — encode "leg sits at lower α" permanently.** Triangular taper
toward the feet means the leg naturally has ~3-5° lower effective α than the
torso. Could be done by shifting `leg.alpha_0` from −2 → +1 or by adding a
`pitchOffset_deg` parameter to `makeWingsuitLiftingSegment`. **Skipped**
because the `legBend` slider already provides this α offset on demand and
re-trimming the downstream `PITCH_HIP_CAMBER_*` / `PITCH_LEG_BEND_*` constants
would be expensive. Comment block left in `A5_LEG_POLAR` for future revisit.

## Skill Update — `browser-dev`

Added a **Trim-Experiment Workflow** section documenting the dev hook,
sweep pattern, and save+diff convention. Also captured these gotchas
discovered today:

- Use HTML ids (`getElementById('alpha-slider')`) instead of label-text walks
  — the label-text approach silently matches the wrong div and fails
  invisibly.
- Inside `run_playwright_code` `page.evaluate` callbacks, **strip TS
  annotations** (`as HTMLInputElement`, `: any`). The runtime is plain JS
  and TS casts produce `Code execution failed: [object Object]` with no
  useful error.
- `lastSystemView` keys are lowercase (`cl/cd/cm/ld`); the readout panel
  uses uppercase string keys with units. Use `lastSystemView` for math.
- Reloading the polar viz silently reverts scenario to "Debug" — re-set
  to `wingsuit-base` after every reload.
