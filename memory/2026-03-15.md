## Key Algorithm Corrections from Hartman

### Cross Product, Not Gradient Descent
- The correction step uses a **cross product** between expected and measured vectors, not gradient descent
- Gives rotation axis + error magnitude in one operation — faster, more mechanical, less versatile
- README updated to reflect this throughout

### Rejection → Dissociation (Better Mental Model)
- "Rejection" is a misnomer — the filter doesn't go gyro-only
- During dissociation, the filter **hallucinates its own reference vectors** from the current quaternion estimate
- Full algorithm keeps running (cross product, gain, everything) but against the filter's own internal model
- The filter is never blind — it's self-consistent but disconnected from reality
- Recovery = **forced reconciliation** — similar to startup, forces the filter to snap back to actual sensor data, dispelling the hallucinations

### Gain Settings — Common Documentation is Wrong
- β ≈ 0.1 (commonly recommended) **doesn't work for real-world motion**
- At low gain, quaternion never converges tight enough → dissociation logic can't establish clean baseline → constant threshold hovering
- **Working range: β ≈ 0.5–1.0** for normal motion (walking, head-mounted, flying)
- Hartman's recommended settings: **β=0.7, accel rejection=25°, mag rejection=25°, recovery=5s**
- At correct gain, dissociation fires cleanly on real disturbances, recovery rarely needed
- "Get gain right first, everything else follows"

### Gain as Trust Dial
- β=0 → pure gyro (drifts immediately)
- β low → under-converged, dissociation unreliable
- β 0.5–1.0 → tight convergence, clean dissociation (recommended)
- β 2+ → over-corrected, jittery
- High gain needed for: startup (quaternion bootstrap), recovery (reconciliation), post-spin re-acquisition
