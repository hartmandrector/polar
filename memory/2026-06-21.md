## Bug 1 — Arrow Keys Hijacked by Dropdowns / Sliders

**Symptom:** Pressing arrow keys while a `<select>` dropdown or slider had
focus changed the dropdown selection / slider value instead of flying.
Clicking the 3D viewport first was required as a workaround.

**Root cause:** The `keydown` listener was registered in the **bubbling
phase** (default). DOM event dispatch visits child elements first, so a
focused `<select>` already processed the key before our `window` handler
ran — `preventDefault()` was too late.

**Fix (`sim-keyboard.ts`):**
1. Both `keydown` and `keyup` listeners switched to `{ capture: true }`.
   Capture phase fires *before* any element, so our `preventDefault()` +
   `stopPropagation()` prevents the dropdown/slider from ever seeing the key.
2. `isEditingTarget()` narrowed to only genuine text-entry inputs
   (`text`, `email`, `password`, `search`, `url`, `number`). `SELECT`,
   `BUTTON`, and `INPUT[type=range]` were removed — flight keys must always
   win over those UI elements.
3. `stopPropagation()` added to `keyup` for CONTROL_KEYS (was missing).

## Bug 2 — Position Trail Freezes While Keys Are Held

**Symptom:** The inertial-frame flight trail stopped adding points while
any control key was held. On key release a "kink" appeared and the trail
resumed from the new position.

**Root cause:** Chromium input-event scheduler priority — the browser
deprioritizes `setInterval` macrotasks when user input events (key repeat
at ~30 Hz) are actively firing. The 100 ms trail-update timer was silently
skipping beats, then firing once on release (producing the kink). Physics
continued correctly because the runner uses `requestAnimationFrame`, which
is never deprioritized.

**Fix (`sim-ui.ts`):**
- `trail.update(runner.state)` moved from `setInterval` into the runner's
  `onUpdate` callback (called via the runner's `requestAnimationFrame` loop).
- A module-level `trailInertialMode` boolean is cached at 10 Hz by the
  `setInterval` (which still handles the HUD readout) and checked in the
  rAF callback — avoids DOM reads at 60 fps.
- `trail.visible` is still set at 10 Hz (sufficient for a mode toggle).

```typescript
// onUpdate now includes:
if (trail && trailInertialMode && runner) trail.update(runner.state)

// setInterval now only does:
trailInertialMode = ctx.getFlightState().frameMode === 'inertial'
if (trail) trail.visible = trailInertialMode
updateHUD(runner, mt, ctx)
```

## Feature — Keyboard Controls Help Overlay

A `⌨ Keys` button added to the bottom of the sim control panel (below the
Start/Stop button). Clicking it opens a floating dark-themed overlay listing
all keyboard bindings grouped by category.

**Dismiss:** click the backdrop, click the `×` button, or press Escape.

**Implementation (`sim-ui.ts`):**
- `createKeyboardHelp(panel)` function builds the button, backdrop div,
  content card with an HTML `<table>`, and wires all close events.
- **Critical ordering:** `createKeyboardHelp()` is called *before*
  `initKeyboard()` in `setupSimUI()`. This ensures the Escape capture
  listener is registered first in the capture chain — `initKeyboard`'s
  capture handler calls `stopPropagation()` which would otherwise swallow
  Escape before the overlay close handler could see it.
- Backdrop click → close; card click → `stopPropagation()` (don't close).
- Escape handler uses `{ capture: true }` to fire before `initKeyboard`'s
  handler.

## Lessons / Notes

- **Capture vs. bubble for flight keys:** always use `{ capture: true }` +
  `stopPropagation()` when flight keys must not be consumed by focused UI
  elements. The order of capture listener registration on the same element
  matters — earlier-registered listeners fire first.
- **Trail / timer vs. rAF:** any update that must be continuous during
  active user input should live in a `requestAnimationFrame` callback, not
  `setInterval`. Chromium will deprioritize timers during high-rate input.
- **`isEditingTarget` scope:** only text-editing inputs (`<input type=text>`
  etc.) and `<textarea>` / `contentEditable` should yield to default key
  behavior. Dropdowns (`<select>`) and range sliders must not intercept
  flight keys.
