# 2026-04-18 — Playwright Capture Integration Fixes

## Participants
- Hartman (founder)
- Polar Claw (main agent, Claude Opus 4.6)

## Summary

Fixed multiple issues with the Playwright PNG capture pipeline. The capture was producing frames with stale/default chart data, wrong capture range, and unreadable control bars. All issues traced to missing synchronization between the capture renderFrame callback and the UI state that chart/moment update functions read from.

## Key Fixes

### 1. Charts & Moment Decomposition Stuck at Frame 0
**Root cause:** `updateChartPolar()` and `updateMomentInset()` both read the current index from `parseInt(scrubber.value)`. During normal playback, `GPSReplay` sets the scrubber via `setCursor()`. The capture `renderFrame` callback was missing both:
- `scrubber.value = String(index)` — so both functions always read index 0
- `charts?.setCursor(index)` — so chart2/chart3 cursors never moved

**Fix:** Added both calls to the capture `renderFrame` callback in gps-main.ts before `updateMomentInset()` and `updateChartPolar()`.

### 2. Capture Not Stopping at End Frame (Race Condition)
**Root cause:** `handleInit()` called `getFlightBounds()` which reads `kfEditor.captureStart/captureEnd`. On the Playwright-launched page, URL auto-config (which parses keyframes from base64) runs asynchronously AFTER `__dataLoaded` is set. If Playwright sends `CAPTURE_INIT` before URL config finishes, `captureStart/captureEnd` are still null → falls back to full flight bounds.

**Fix:** `handleInit()` now reads `startTime`/`endTime`/`frameRate`/`totalFrames` from URL query params as fallback. `buildCaptureUrl()` bakes these into the URL. Priority: CAPTURE_INIT message → URL params → getFlightBounds() auto-detect.

### 3. Transparent Backgrounds for PNG Capture
- `#charts-panel` background changed from `#16213e` to `transparent`
- Added CSS rules making `#speed-polar-chart`, `#moment-panel`, `#readout-panel` and their headers/canvases transparent
- Moment-inset Three.js background plane opacity changed from 0.75 to 0 (was a PlaneGeometry with MeshBasicMaterial)
- Playwright uses `omitBackground: true` to get transparent PNGs

### 4. DOM IDs for Playwright Targeting
- `#polar-curve-select` (was unnamed `chart1-select`)
- `#speed-polar-chart` on chart container div
- `gps-charts.ts` updated to use new `polar-curve-select` ID

### 5. Unicode Bar Characters Not Rendering in Screenshots
**Root cause:** `█` (U+2588) and `░` (U+2591) block characters in moment-wingsuit.ts and moment-canopy.ts rendered poorly at 10px monospace in headless Chromium screenshots.

**Fix:** Replaced with HTML `<span>` elements using inline CSS backgrounds (6×8px cells, `#ccc` filled, `rgba(255,255,255,0.15)` empty). Same visual layout, guaranteed readable in screenshots.

## Architecture Notes

### Capture Protocol (page ↔ Playwright)
1. User clicks Capture → POST to `localhost:3333/capture-polar` with `{totalFrames, frameRate, startTime, endTime, url, session}`
2. Playwright navigates to `url` (has all state as query params)
3. Page loads data → sets `window.__dataLoaded = true`, then async URL config → `window.__sessionReady = true`
4. Playwright sends `postMessage({type: 'CAPTURE_INIT', frameRate, startTime?, endTime?})`
5. Page responds with `CAPTURE_READY` + sets `window.__captureReady`
6. Playwright loops: `REQUEST_FRAME(frame)` → page renders → `FRAME_READY(frame)` + `window.__lastRenderedFrame = frame`
7. Time mapping: `t = startTime + frame / frameRate`

### Key Lesson: Scrubber as Shared State
`updateChartPolar()` and `updateMomentInset()` use `parseInt(scrubber.value)` as the current frame index — NOT a direct parameter. Any new rendering path (capture, seek, external control) must update the scrubber value before calling these functions.
