# 2026-03-24 — Kalman Filter Architecture Analysis

## Kalman Project Study (`/mnt/c/dev/kalman/`)

Hartman asked for analysis of adapting existing Kalman filter for orientation estimation in polar-visualizer.

### Existing Kalman Architecture
- **12-state EKF**: `[x, y, z, vx, vy, vz, ax, ay, az, kl, kd, roll]` in ENU
- **Physics-based prediction**: `calculateWingsuitAcceleration(v, kl, kd, roll)` propagates state
- **Measurements**: GPS position + velocity (6 measurements)
- **kl/kd/roll**: Extracted from Kalman-filtered velocity+acceleration via `calculateWingsuitParameters()` — same decomposition as polar-visualizer's `wse.ts`
- **Wind sub-filter**: Separate 3-state Kalman (wx, wy, wz). Gradient descent finds wind minimizing acceleration residual against polar model.
- **Step smoothing**: Blends out measurement jump linearly over one GPS interval → smooth 90 Hz output from 5-20 Hz GPS
- **`predictAt(timestamp)`**: Forward-predicts using physics model between GPS updates — exact interpolation pattern needed for VR/replay
- **Adaptive Q/R**: NIS-based tuning (position, velocity separately) — Hartman said ignore this complexity

### Proposed Orientation Kalman State Vector
Two options discussed:
- **9-state (no controls)**: `[φ, θ, ψ, p, q, r, ṗ, q̇, ṙ]`
- **13-state (with controls)**: `[φ, θ, ψ, p, q, r, ṗ, q̇, ṙ, α, pitchThrottle, rollThrottle, yawThrottle]`

Parallel structure to translational filter:
- position↔orientation, velocity↔body rates, acceleration↔angular accel, aero params (kl,kd,roll)↔control inputs

### Key Insight: Controls as State Variables
Including pitchThrottle/rollThrottle/yawThrottle in state vector would **replace Newton-Raphson inverse solver (Pass 2)** entirely. Kalman naturally estimates controls needed to explain measured orientation changes. Process noise on controls = how fast pilot inputs can change.

### Prediction Model
1. Evaluate segment model at current α with current control estimates → moments
2. `rotationalEOM(moments, inertia, omega)` → angular acceleration
3. Integrate: ṗ,q̇,ṙ → p,q,r → φ,θ,ψ via kinematic equations (DKE)

### SG vs Kalman: Run Parallel
Recommendation: SG pipeline stays as batch-optimal ground truth (same role as in Kalman-viz project). Kalman adds physics-interpolated output for replay + natural 60fps smoothing + control estimation. Not a replacement — complementary.

### What to Reuse from Kalman Project
- Matrix library (works, tested)
- Step smoothing concept
- Wind sub-filter structure
- `predictAt(timestamp)` pattern

### What to Drop
- Adaptive Q/R NIS machinery
- Optimizer infrastructure
- ENU↔NED conversions (stay NED throughout)

## Afternoon Session — AeroMomentAdapter + EKF Wiring

### AeroMomentAdapter Built (`src/kalman/aero-adapter.ts`)
- Wraps `evaluateAeroForces()` from segment model → `AeroMomentModel` interface
- **Vehicle-agnostic**: takes segments/CG/height/inertia at construction, works for any vehicle
- **Pluggable control mapper**: default is wingsuit (pitchThrottle/rollThrottle/yawThrottle), swap in canopy mapper later for brakes/risers/weightShift
- **Ground handling**: below 5 m/s airspeed, returns zero moments (filter kinematic-only at low V)
- `NEUTRAL_CONTROLS` spread + override pattern for SegmentControls (22+ fields)

### EKF Runner Built (`src/kalman/ekf-runner.ts`)
- Glue between `src/gps/` pipeline and `src/kalman/` EKF
- `runOrientationEKF(points, config)` → feeds each GPSPipelinePoint as measurement, returns estimates + live EKF
- Converts pipeline body rates from deg/s → rad/s
- Sets airspeed per timestep for aero model evaluation

### GPS Viewer Wired
- `gps-main.ts`: runs EKF after control inversion batch, passes `ekf` to scene
- `gps-scene.ts`: `setEKF()` method, `setIndex()` uses `predictAt(tInterp)` for physics-interpolated orientation between GPS samples
- Position still lerped from GPS; orientation now fully EKF-driven

### First Test Results
- 474/1312 control inversion converged (expected — full flight includes deploy/canopy phases interpreted as wingsuit)
- 1312 EKF points in 0.226s — fast enough
- **Model pitched to ~90° AOA** — EKF θ diverged because α was unobserved

### α Promoted to 7th Measurement (Fix)
- Root cause: α started at 0 in state vector, no measurement constrained it, aero model evaluated moments at wrong α → θ diverged
- Changed `MEAS_SIZE = 6 → 7`, added `MeasIdx.ALPHA = 6`
- H matrix maps measurement 6 → state index 9 (StateIdx.ALPHA)
- `rAlpha = 0.05` (~3° measurement noise)
- α initialized from first pipeline AOA, updated every sample from `extractAero().aoa`
- All compiles clean

### Architecture Notes (from Hartman)
- Adapter must handle any assembled vehicle long-term (canopy on top of wingsuit, mode transitions)
- Kalman filter is a flying filter — doesn't work well on ground, needs acceleration guards for static GPS
- Processing flow: wingsuit estimation → then canopy estimation layered on top (mirrors real flight sequence)
- Canopy will need pilot pitch estimation eventually but not yet — no canopy mode built
