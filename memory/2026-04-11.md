## 2026-04-11 Evening — Bugfixes + Aero Tuning Revert

### Race Conditions Fixed
1. **Head sensor data race** — `setHeadSensorData()` silently dropped data when `headRenderer` was null (GLB still loading). Fix: queue sensor data in `pendingSensorData`, apply after model loads. Both `GPSScene` and `BodyFrameScene`.
2. **Head model visibility race** — `loadModel()` unconditionally set `headGroup.visible = false` after async GLB load, overwriting `setSensorData()`'s `visible = true`. Fix: check `sensorData.length > 0` on model load complete.
3. **OrbitControls damping conflict with keyframes** — `setCameraState()` set camera position, but OrbitControls with `enableDamping = true` stored momentum in internal spherical state and drifted camera away. Fix: temporarily disable damping → set position → `controls.update()` → re-enable damping. Removed `keyframeOverride` flag approach (was worse — caused stale damping accumulation).
4. **Capture handler missing keyframe application** — `renderFrame` callback in capture handler didn't call `applyKeyframeCameras(t)`. Playwright captures rendered with default camera. Fixed.
5. **Initial keyframe application** — after URL auto-config, `applyKeyframeCameras()` now called at first keyframe time so camera starts correctly.

### GPS Aero Overlay — CP Doesn't Respond to Control Inputs (open issue)
- `gps-aero-overlay.ts` line 221: `this.controls = defaultControls()` — always evaluates with neutral controls
- Control solver runs (Pass 2) but results stored in `lastControls` for display only, not fed back to segment force/CP computation
- Reason: solver mutates segment `position.y` and `orientation`, corrupting next frame's neutral eval. Snapshot/restore pattern already exists for solver.
- **Proposed fix**: Run second evaluation with solved controls just for CP diamond positions, using same snapshot/restore approach. Arrows stay neutral (physically meaningful), CP diamonds shift with controls.
- Hartman wants CP diamonds to reflect solved controls (e.g., 21% pitch → CPs shift aft)

- Options discussed: reduce PITCH_CP_SHIFT, per-segment CP shift gain, clamp cp_min, taper with span
- **Not yet resolved** — Hartman reviewing options
