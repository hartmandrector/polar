## Moment Breakdown Inset (commit `6fda9a1`)
- `MomentInset` class in `src/gps-viewer/moment-inset.ts`
- Mini Three.js renderer (280×260px) bottom-left of 3D scene
- Three gauge clusters: PITCH, ROLL, YAW
- Concentric curved arrows per axis:
  - Orange: aero moment (suit demand)
  - Green: pilot control input (placeholder — zero until Pass 2)
  - Yellow: gyroscopic coupling
  - White: net residual
- Monospace legend with live numeric values in N·m
- `GPSAeroOverlay.lastMoments` populated after each evaluation, fed to inset

## Two-Pass Control Inversion Architecture (planned)
- **Pass 1 (done)**: Forward model — GPS state + neutral controls → predicted forces/moments
- **Pass 2 (next)**: Inverse solve — compare predicted vs measured accelerations, solve for control vector that closes the gap
- Control outputs in [-1,1] / [0,1] range (same as gamepad) — directly comparable to sim inputs
- Wingsuit: 3 unknowns (pitch/roll/yaw), 3 moment axes — square system
- Validation: if solved controls are in physically reasonable range, model moments are correct
- Key insight: moment arcs will shrink to near-zero after Pass 2 (net residual), so the inset preserves the component decomposition that would otherwise be lost
