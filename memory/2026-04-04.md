# 2026-04-04 — PC/Bridle Attachment Fix (In Progress)

## Problem
After line stretch, the PC and bridle render attached to the pilot's back instead of trailing from the canopy top. The DeployRenderer was using the wingsuit model quaternion and pilot-CG-relative positions for all phases, which is wrong post-line-stretch.

## Fixes Applied (commits e1bfef4 → f98ec34)
- **Canopy quaternion**: Post-LS, `deployQuat` uses `effectiveCs` (canopy estimator orientation) instead of `this.model.quaternion` (pilot/wingsuit)
- **Canopy-relative coords**: Post-LS segment positions are canopy-CG-relative (origin at canopy), PC at `(-chainLength, 0, 0)` in canopy NED
- **Anchor at canopy origin**: Post-LS anchor is `(0,0,0)` in scene coords (canopy frame origin)
- **Full flight visibility**: `isDeploying` now includes `full_flight` so PC/bridle persist through entire canopy ride
- **Pre-LS unchanged**: PC toss, bridle stretch still use pilot model quat + pilot-CG-relative positions

## Key Insights
- `bodyQuat` in gps-scene.ts deploy call was `this.model.quaternion` — the wingsuit GLB orientation, NOT canopy orientation
- `effectiveCs` from canopy estimator has the correct canopy phi/theta/psi → use `bodyToInertialQuat()` for deploy rendering
- DeployRenderer `toScene()` applies `nedToThree(ned, scale)` then rotates by bodyQuat — positions must be in the frame matching bodyQuat
- DeployRenderer anchor: if not provided, uses default mid-back (wrong for canopy); must pass explicit anchor
- `isDeploying` excluded `full_flight` — PC disappeared after surge phase

### Chain Length Fix (commit 8e5f981)

- Pre-LS: full 7.4m chain, segments at `PRE_LS_SEGMENT_LENGTH = 0.74m`
- Post-LS: bridle only 3.3m, segments at `POST_LS_SEGMENT_LENGTH = 0.33m`

### Ground Mode Cleanup (commit ad47c29)

### PC Orientation (commits 8431e1f → 8070588 → 098bc78)
- Problem: PC rotated 90° in GPS replay because chain is straight line (pure -Z in Three.js), `orientAlongChain` with fixed up vector `(0,1,0)` gives wrong roll
- Attempt 1: Static 90° Z rotation offset — wrong axis, didn't match all orientations
- Attempt 2: Dynamic canopy bodyQuat as offset — caused wild spinning
- Attempt 3 (current): Copy last visible bridle segment's quaternion onto PC. Segments already oriented by `orientAlongChain` with proper chain context. Uses `pcRotationOffset` as flag (non-null = copy-from-segment mode). **Still testing**
- Sim's PC orientation unchanged — falls back to direct `orientAlongChain` when `pcRotationOffset = null`

### Key Realization
- Bridle sim in the simulation lives in inertial frame, but attachment is defined in body frame — body→inertial→sim→body round-trip. GPS replay doesn't do this round-trip, which is why orientations come out wrong
- Long-term fix: run actual bridle sim in GPS replay (inertial frame with body-frame constraints). Current approach is approximation

## Architecture Note
- `GPSDeployRenderer` (gps-deploy-renderer.ts) synthesizes `WingsuitDeployRenderState` from `DeployReplayTimeline`
- `DeployRenderer` (deploy-render.ts) does actual Three.js rendering — anchor → segments → PC chain
- `gps-scene.ts` calls `deployRenderer.update(index, pt, bodyQuat, canopyModel)` — bodyQuat choice is critical
