# 2026-03-30 — PNG Capture Pipeline

## What was built

Full PNG frame capture pipeline between polar-visualizer and playwright-capture projects.

### Polar-visualizer side
- `src/gps-viewer/capture-handler.ts` — postMessage protocol handler
  - `CAPTURE_INIT` → `CAPTURE_READY` (negotiate frame range)
  - `REQUEST_FRAME` → binary-search interpolation → render → `FRAME_READY`
  - Auto-detects flight bounds from flight computer modes (wingsuit onset → end of data)
  - Button click POSTs to `http://localhost:3333/capture-polar`
  - Sets `window.__dataLoaded` and `window.__lastRenderedFrame` for playwright detection
  - Extracts flight date from CSV ISO timestamp for folder naming
- Sidebar "PNG Capture" section at bottom: red button + status + frame counter
- Wired into `gps-main.ts`: renderFrame callback drives both scenes + legends + moment inset
- Commits: `81b3953`, `6ea2808`

### Playwright-capture side
- `/capture-polar` server route in `src/server.ts` — launches `polar-capture.test.ts`
- `tests/polar-capture.test.ts` — much simpler than CloudBASE capture (no login, no DevTunnel)
  - Navigates to `localhost:5173/gps`, waits for `__dataLoaded`
  - Sends `CAPTURE_INIT`, waits for `CAPTURE_READY`
  - Three screenshot targets per frame (parallel): dual, inertial, body
  - Resume support: detects existing PNGs, skips to resume point
  - Folder naming: `polar-dual_<flightDate>`, `polar-inertial_<flightDate>`, `polar-body_<flightDate>`
  - Transparent backgrounds (`omitBackground: true`) for compositing
- Commit: `c5f5a91`

### Planning doc
- `docs/PNG-CAPTURE.md` — full architecture, protocol, implementation order, math estimates

## Key decisions
- **Output interpolation** (not input upsampling) — lerp all displayed quantities at render time
- **No start/stop sliders** — flight computer mode data gives natural boundaries
- **Three separate screenshot targets** — dual, inertial-only, body-only for flexible compositing
- **Flight date from CSV ISO timestamp** — parsed from first data line for folder naming
- **postMessage protocol** (not WebSocket) — simpler, matches existing CloudBASE capture pattern
- **Resume support** — detect existing frames, skip to resume point

## Evening Session — Head Model + Sensor Overlay

### Head model rendering (Phase 1-2 of HEAD-POSITION.md)
- `head-sensor.ts` — parser for fused sensor fusion CSV (`SENSOR_fused_fusion (1).csv`)
  - 51 columns, ~13Hz, NWU frame
  - Extracts: timestamp, roll/pitch/yaw (deg), qw/qx/qy/qz, accel_body, gyro, gravity_body, linear_accel, GPS sync
  - Binary search + fraction for time interpolation between sensor points
- `head-renderer.ts` — loads `fullhead.gltf`, attaches to wingsuit via Three.js scene graph
  - NWU→NED Euler conversion: `roll_ned = roll_nwu`, `pitch_ned = pitch_nwu` (NOT negated — tested), `yaw_ned = -yaw_nwu`
  - Reuses `bodyToInertialQuat()` from frames.ts for proven NED→Three.js mapping
  - Relative rotation: `q_head_relative = q_wingsuit⁻¹ × q_head` — Three.js parent-child composition handles the rest
  - Slerp interpolation between sensor points for smooth ~13Hz→60fps motion
  - HEAD_MODEL_ROTATION = 90° pitch to align head model forward with wingsuit forward
  - HEAD_SCALE = 0.1 (tuned from initial 0.01)
  - NECK_OFFSET tuned by Hartman to seat on wingsuit neck stump
- Both inertial and body frame scenes have head model
- Sidebar "Head Sensor" panel: blue Load button, file input, time offset field, status
- Commits: `546e1ad` (initial), `93ce2ff` (sensor overlay)

### Sensor vector overlay
- `head-sensor-overlay.ts` — vectors originating from sensor position (top of head)
  - SENSOR_OFFSET = (0, 0.12, 0) above neck attachment — positions at FlySight device
  - **ShadedArrow** (fancy gradient arrows): accel (yellow), gravity (green)
  - **CurvedArrow** (arc arrows): gyro p/q/r (red/green/blue) around body axes
  - All children of headGroup — move/rotate with head automatically
  - ACCEL_SCALE/GRAVITY_SCALE = 0.12, GYRO_SCALE = 0.005, GYRO_ARC_RADIUS = 0.08

### Tuning status
- Head position and scale: ✅ tuned by Hartman, looks good

### Key learnings
- Head model initial offset was in inertial Y-up instead of model-local space — fixed by using model-local coordinates as child of wingsuit
- Scale was 10× too small initially (0.01 → 0.1)
- Head model needed 90° rotation to face forward (different GLB convention than wingsuit)
- NWU→NED pitch sign: do NOT negate — same direction in both frames (tested empirically)
