# 2026-04-16 — Control Solver Canopy Mode + Moment Inset Refactor

## Participants
- Hartman (founder)
- Polar Claw (main agent, Claude Opus 4.6)

## Summary

First session after hitting context window limit and starting fresh with /new. Built mode-aware control solver visualization for the canopy, fixed a critical bug where canopy solved controls weren't reaching the speed polar, and discovered + fixed the missing gravity torque in the canopy solver that was causing inverted control results.

## Key Findings

1. **Speed polar bug**: `updateChartPolar()` used `??` fallback — wingsuit `defaultControls()` always won over canopy solved controls because `solvedSegmentControls` was never null. Fixed with flight-mode dispatch.

2. **Canopy solver gravity torque**: The solver was trying to explain ~3600 N·m of gravity restoring moment (pilot mass × g × riser length × sin(bank)) with aero controls alone. This caused controls to saturate at 100% and appear inverted. Fix: subtract gravity torque from required moments before solving.

3. **Body rates are correct**: Verified inverse DKE in `wse.ts` uses standard NED convention. The GPS pipeline body rates were not the issue.

4. **Sideslip = 0**: Body velocity in solver uses `y = 0` (no sideslip). Known limitation for turn accuracy.

## Decisions Made

- Moment inset uses **pluggable mode formatters** — one file per vehicle mode, extensible to deploy/ground/freefall
- Auto-detect mode from `flightMode` — **no manual override dropdown**
- Canopy solver uses **auto-select constraint** (try brakes-only + risers-only, pick lower residual) instead of solving all 4 controls simultaneously
- `canopyControlGain = 3.0` as temporary multiplier — remove when segment model authority is tuned
- Relative convergence threshold `max(0.5, |M_req| × 5%)` for canopy scale
- Riser length hardcoded at 6.0m — derive from canopy geometry later
- Control solver checkbox defaults to checked

## Files Created
- `gps-viewer/moment-types.ts` — shared types: VehicleMode, AxisMoments, CanopyControlMap, MomentLegendFormatter
- `gps-viewer/moment-wingsuit.ts` — wingsuit legend formatter (±100% bipolar bars)
- `gps-viewer/moment-canopy.ts` — canopy legend formatter (0-100% unipolar bars + control→axis mapping)
- `docs/CONTROL-SOLVER.md` — comprehensive solver documentation

## Files Modified
- `gps-viewer/moment-inset.ts` — refactored with setMode(), pluggable formatters, sizing/spacing
- `gps-viewer/control-solver.ts` — canopy gravity torque, auto-select constraint, control map, relative threshold, canopyControlGain
- `gps-viewer/gps-aero-overlay.ts` — expose raw canopy controls + control map, pass phi/theta/riserLength to solver
- `gps-viewer/gps-scene.ts` — expose canopyCanopyControls + controlMap in lastOverlayState
- `gps-viewer/gps-main.ts` — flight-mode-aware updateMomentInset() and updateChartPolar()
- `gps-viewer/body-frame-scene.ts` — setCanopyConstraint method
- `gps.html` — control solver checkbox defaults checked

### Sim vs Solver Gravity Finding
Important architectural note: the **sim** includes gravity torque for canopy via `pilotPendulumEOM()` (pitch pendulum), `pilotLateralEOM()` (roll spring/damper), and `linetwistEOM()` (yaw spring). The **GPS solver** previously had NONE of this. We added first-order gravity torque (`-m*g*L*sin(φ/θ)`) to the canopy solver, which dramatically improved results. The full pendulum coupling (damping, canopy-pilot feedback) is still missing from the solver — documented as known limitation in `docs/CONTROL-SOLVER.md`.
